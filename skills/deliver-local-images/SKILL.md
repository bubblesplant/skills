# 本地图片可靠交付

把“生成图片”和“用户实际看见图片”视为两个必须分别完成的步骤。除非用户只要求文字描述，否则不得把工具临时预览当作最终交付。

## 交付流程

1. 将最终图片保存为真实文件。项目相关图片优先保存到当前工作区；临时预览保存到当前任务可写的 visualization 目录。默认使用 PNG，照片可使用 JPEG/WebP。
2. 如果图片位于系统临时目录、工具缓存或用户不可访问的位置，先复制到当前工作区或当前任务可写目录。不要让最终交付只存在于图片生成工具的临时输出中。
3. 发送前检查：
   - 文件路径存在；
   - 文件长度大于 0；
   - 图片可以解码，宽高合理；
   - 使用 `view_image` 做一次视觉检查，确认不是空白图、错误图或损坏图。
4. 最终回复必须直接嵌入图片，并紧接一个可点击的原图链接。Windows 路径使用绝对路径和正斜杠：

   ```markdown
   ![简短中文说明](C:/absolute/path/result.png)

   [点击打开原图](C:/absolute/path/result.png)
   ```

5. 路径包含空格时，用尖括号包住 Markdown 目标：

   ```markdown
   ![简短中文说明](<C:/path with spaces/result.png>)
   ```

6. 多张图片逐张嵌入，不要只给目录链接。

## 强制规则

- 不要使用相对路径、`file://` URI 或仅用反引号展示文件路径。
- 不要只说“见上图”“已生成”或“图片在上方”。
- 不要在没有本地文件和验证结果时声称图片已经交付。
- 如果内置图片生成工具未返回可落盘文件或客户端未显示结果，不要重复同一种无文件交付。能忠实复现时，改用本地绘制、合成或导出生成真实图片；不能忠实复现时，明确说明失败原因，并在需要 CLI/API 回退时先征得用户同意。
- 即使图片已经通过工具消息显示，最终回复仍应优先附上本地绝对路径版本，确保用户可以再次打开。

## 完成标准

只有同时满足以下条件才算完成：图片真实落盘、通过视觉检查、回复中成功使用绝对路径内嵌、提供可点击原图链接。
