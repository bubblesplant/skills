# 管理带前缀的定时通知

## 范围

仅管理属于下方 AI 自有命名空间的定时提醒、通知、计划通知记录和定时任务。本 skill 定义边界、命名规则和通知行为，不固定具体脚本或命令配方；根据操作系统选择合适的系统级调度器、原生通知 API 或系统通知命令。

## 命名空间

始终使用：

- 所有者命名空间：`AI-Reminders`
- 资源前缀：`AI-Reminder-`
- 生成 ID 格式：`AI-Reminder-<stable-id>`

平台支持调度器文件夹、组、标签、单元名、注释、描述或元数据时，用上述名称标记资源：

- Windows：`AI-Reminders` 作计划任务容器；任务名以 `AI-Reminder-` 开头。
- macOS：launch label、文件名或调度器元数据以 `AI-Reminder-` 开头或明确包含 `AI-Reminders`。
- Linux：用户级调度器资源、unit 名、job 名、注释或元数据以 `AI-Reminder-` 开头或明确包含 `AI-Reminders`。

## 目录授权（硬性前置）

- 只有用户在当前对话任一消息中明确提供提醒管理目录后，才可执行任何创建、列出、查看、更新、删除或审计；目录检查必须先于时间确认、过期检查、调度器查询和文件系统查询。
- 先检查完整对话上下文（含较早消息）：已有用户明确提供的目录时直接复用，不再询问；存在多个时使用最近一次提供的。
- 上下文中没有用户明确提供的目录时，回复“请提供用于存放和管理提醒文件的目录路径。”并立即停止本回合——不得先查询或变更调度器、检查过期提醒、搜索或创建文件。
- 严禁把 `cwd`、工作区、环境上下文路径、项目目录、临时目录、默认目录、历史提醒目录或模型自选路径当作用户目录，即使可写。
- 用户目录是本次操作的根目录和范围：只在该目录内读写受控元数据、辅助文件和日志，只管理能确认与该目录关联的 `AI-Reminder-*` 调度器资源。
- 创建新任务时，在用户目录下新建 `<日期>/<某一项任务>/` 子目录，不放入其他任务目录、不复用历史任务的父目录。
- 列出、查看、更新、删除、审计时，只处理目录范围内且归属明确的提醒；元数据目录与用户提供目录不一致或无法确认归属时，停止并说明差异，不得转用其他目录。
- 每次操作后在回复末尾补充“目录位置：`...`”；用户未提供目录而操作被阻止时写“目录位置：未设置”。

## 执行规则

- 默认创建操作系统用户级计划通知，必须在指定时间产生真实可见的系统通知。不得用会话心跳、聊天内提醒、宿主应用通知、应用内回访或托管自动化平台替代；用户明确要求会话内提醒时，说明本 skill 只管操作系统级提醒。
- 通知必须使用操作系统原生能力；原生不可用时仅用系统内清晰可见的本地兜底通知，并说明所用兜底方式。
- 创建或更新前确认当前日期、时间和时区。`11.58`、`11:58` 解析为本地 `HH:mm`；省略日期且该时间今天未过时用今天，已过时询问用户补跑、明天或其他日期。
- 创建提醒时，若当前回合尚未列出范围内提醒，先检查 `AI-Reminders` / `AI-Reminder-*` 中的过期提醒（一次性提醒计划时间已过，或任务无未来运行时间）。存在时用 Markdown 表格展示并询问是否删除；用户未明确要求前不得擅自删除。
- 调度器或通知访问被权限、沙箱或登录状态阻止时，请求所需权限；不静默降级，仅在首选方式不可用、被阻止或验证不适合时使用兜底，并说明。

## 通知执行指导

- 使用操作系统用户级调度器加系统通知能力（Windows 任务计划程序 + 可见通知；macOS `launchd`/`osascript`/通知中心；Linux 用户级 `systemd` timer、`cron` 或桌面通知命令）。
- 按重要性选择通知方式：
  - **重要**：直接使用操作系统本地模态弹窗，backend 记为 `popup-important`。
  - **一般**：优先系统级 Toast，不可用时兜底模态弹窗，backend 记为 `toast` 或 `popup-fallback`。
- Windows Toast：用 `powershell.exe` 或已可用的 `pwsh.exe`，以 PowerShell 自身 AppID 发起；不注册自定义 AppID、不创建开始菜单快捷方式；优先 Windows Toast/WinRT API，不默认依赖第三方模块。
- 操作系统可直接创建计划通知时，不强制 `.ps1` 等辅助文件；辅助文件只是实现细节。需要可执行动作时，选系统中最小且可靠的动作（脚本、快捷指令、job 动作、系统通知命令等），并写入元数据。
- 生成辅助脚本时确保适配环境：避免编码敏感的本地化字面量（中文等），通过参数或元数据传递本地化标题/消息；主要通知可能不可见时包含可见兜底；实际可行时写简短成功/失败日志。
- 创建或修改后实际可行时验证通知动作（运行一次无害短测试确认能成功），再依赖计划时间。
- 生成的辅助脚本、元数据、日志是该提醒的受控相邻产物；`powershell.exe`、`schtasks.exe`、shell 解释器、通知守护进程、共享运行时等不是受控产物。

## 安全规则

- 仅管理明确用于定时提醒且属于 `AI-Reminder-` 前缀或 `AI-Reminders` 命名空间的资源；其余一律视为范围外。
- 不创建、更新、禁用、启用或删除无关计划任务；不操作宽泛调度器路径、全部 jobs、全部启动项、厂商更新、安全软件、浏览器更新或操作系统托管任务。
- 用户要求修改范围外任务时，说明本 skill 只管理带前缀的提醒资源。
- 优先用户级计划任务；仅当用户明确要求系统级任务并理解权限影响时才用系统级。
- 删除、覆盖、禁用等破坏性操作前，确认精确的资源名称或 ID。

## 操作规则

通用约束（所有操作适用）：

- 遵循“目录授权”规则解析目录，不重复判断。
- 仅操作带前缀资源；创建前检查过期提醒；操作后报告提醒 ID、平台资源名称、通知方式和目录位置。

创建：

- 在用户目录下创建独立子目录，生成 `AI-Reminder-` 前缀的稳定 ID。
- 保存完整元数据：标题、消息、时间、循环规则、重要性、用户意图、通知 backend、平台动作、元数据路径，及存在时的辅助文件/日志路径。
- 平台支持时启用错过时间后的补跑；创建后验证平台资源存在。

列出：

- 仅列出能确认属于用户目录的提醒；无匹配时清楚说明未找到。
- 用 Markdown 表格返回，固定列：`序号` | `ID` | `标题` | `重要性` | `计划时间` | `循环规则` | `状态` | `下次运行` | `上次运行` | `通知方式` | `目录位置`

查看：

- 仅查看能确认属于用户目录的提醒；用表格展示单个资源关键字段，补充不一致、权限限制或执行失败详情；元数据与调度器资源不一致时明确报告差异。

更新：

- 仅更新用户目录内的提醒；原目录不一致时停止并说明，不沿用或转移。
- 保留稳定 ID，仅修改匹配前缀的资源及其受控元数据；仅当原地更新不安全或平台不支持时才重建受控资源。

删除：

- 仅删除用户目录内归属明确的、用户指定的精确带前缀资源及其受控相邻产物（元数据、辅助脚本、日志）。
- 删除前确认每个产物明确归属于该精确提醒 ID；删除后报告已删除的调度器资源和相邻产物。

审计：

- 仅检查用户目录范围内 `AI-Reminders` 命名空间的孤立元数据或孤立计划任务资源；仅为受控资源提供修复建议或修复操作。

## 用户沟通

使用用户的语言回复。仅当完整对话上下文中没有用户明确提供的目录时才请求目录并停止；已有目录时直接复用不重复询问。无法安全访问调度器或通知系统时，说明阻碍因素及所需权限或登录状态。

## 已知问题：Windows 通知中文乱码（编码陷阱）

**现象**：计划任务触发的弹窗/通知中中文显示为乱码（mojibake）。

**根因**：Windows PowerShell 5.1 解析无 BOM 的 `.ps1` 时按系统 ANSI 代码页（中文 Windows 为 GBK）解码。编辑器/写文件工具默认保存为 UTF-8 无 BOM，脚本里硬编码的 UTF-8 中文字面量被按 GBK 误读成乱码；Toast XML 模板中的中文同理。

**修复方案（推荐组合使用）**：

1. **脚本只写 ASCII 代码，中文从元数据读取**：`.ps1` 内不出现中文字面量，标题/消息经 `Get-Content -Raw -Encoding UTF8 metadata.json | ConvertFrom-Json` 读取（PowerShell 字符串内部为 UTF-16，读入即正确），彻底免疫文件编码问题。
2. **脚本保存为 UTF-8 with BOM**：写盘后用 `[System.IO.File]::WriteAllText($path, $text, [System.Text.UTF8Encoding]::new($true))` 补 BOM（`EF BB BF`），PowerShell 5.1 检测到 BOM 后按 UTF-8 正确解析。
3. 创建后**必须实测一次通知动作**，确认中文显示正常再依赖计划时间。

**排查方法**：读取脚本前 3 字节，为 `EF BB BF` 则带 BOM；否则是无 BOM UTF-8，在中文 Windows 上会被误读为 GBK。
