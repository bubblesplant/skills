# 管理带前缀的定时通知

## 范围

仅将此 skill 用于属于下方 AI 自有命名空间的定时提醒、通知、计划通知记录和定时任务。

此 skill 定义边界、命名规则和通知行为；不固定某一个脚本或命令配方。根据操作系统选择合适的系统级调度器、原生通知 API 或系统通知命令。

## 默认执行规则

- 用户要求提醒、通知或计划通知时，默认创建操作系统用户级计划通知。计划项必须在指定时间产生真实可见的系统通知。
- 不要用当前对话、会话心跳、对话回访、聊天内提醒、宿主应用通知、非操作系统的应用心跳、聊天通知、托管自动化平台或应用内回访替代系统通知。若用户明确要求这类会话内提醒，说明此 skill 只管理操作系统级提醒。
- 用户要求通知时，必须使用操作系统原生通知能力。原生通知不可用时，仅可使用操作系统内清晰可见的本地兜底通知，并说明所用兜底方式。
- 创建或更新提醒前，确认当前日期、时间和时区。将 `11.58` 和 `11:58` 解析为本地 `HH:mm`。用户省略日期且该时间今天尚未过去时，使用今天；如果时间已经过去，询问用户是要今天补跑、明天，还是其他日期。
- 创建提醒时，如果当前回合尚未查询或列出范围内提醒，先检查 `AI-Reminders` / `AI-Reminder-*` 资源中是否存在过期提醒。过期指一次性提醒的计划时间已在过去，或定时任务在计划时间过去后没有未来运行时间。若存在过期提醒，用 Markdown 表格展示，并询问用户是否删除。除非用户已明确要求删除，否则不要擅自删除过期提醒。
- 如果操作系统调度器或通知访问被权限、沙箱或用户登录状态限制阻止，请请求所需权限。不要静默降级到无法满足用户请求的提醒机制；仅当首选方式不可用、被阻止或已验证不适合时，才可使用兜底方式，并说明所用兜底方式。

## 命名空间

始终使用这些名称：

- 所有者命名空间：`AI-Reminders`
- 资源前缀：`AI-Reminder-`
- 生成 ID 格式：`AI-Reminder-<stable-id>`

平台支持调度器文件夹、组、标签、单元名、注释、描述或元数据时，用所有者命名空间和资源前缀标记资源。

平台命名指导：

- Windows：可用时，将 `AI-Reminders` 作为计划任务容器命名空间；任务名必须以 `AI-Reminder-` 开头。
- macOS：launch label、文件名或调度器元数据必须以 `AI-Reminder-` 开头，或明确包含 `AI-Reminders`。
- Linux：用户级调度器资源、unit 名、job 名、注释或元数据必须以 `AI-Reminder-` 开头，或明确包含 `AI-Reminders`。

## 通知执行指导

- 必须使用操作系统提供的用户级调度器和系统通知能力。例如 Windows 任务计划程序加 Windows 可见通知动作，macOS `launchd`/`osascript`/通知中心，Linux 用户级 `systemd` timer、`cron` 或桌面通知命令。
- 根据用户描述判断通知重要性，按重要性选择通知方式：
  - **重要通知**：直接使用操作系统本地模态弹窗，确保用户不会错过。将 backend 记录为 `popup-important`。
  - **一般通知**：优先使用操作系统级 Toast 通知；Toast 不可用时兜底为本地模态弹窗。将 backend 记录为 `toast` 或 `popup-fallback`。
- Windows Toast 实现方式：使用 `powershell.exe` 或已可用的 `pwsh.exe`，直接以 PowerShell 自身的 AppID 发起 Toast 通知，不要注册自定义 AppID 或创建开始菜单快捷方式。优先用 PowerShell 调用 Windows Toast/WinRT 通知 API，不要默认依赖第三方模块。
- 当操作系统可以直接创建计划通知时，不要强制要求 `.ps1`、shell 脚本或辅助可执行文件。辅助文件只是实现细节，不是此 skill 的公开契约。
- 操作系统要求可执行动作时，选择该系统中最小且可靠的通知动作，并写入元数据。动作可以是脚本、快捷指令、计划 job 动作、系统通知命令或操作系统特定通知资源。
- 生成辅助脚本或小型辅助可执行文件时，确保它适配环境：避免依赖编码敏感的本地化字面量；可行时通过参数或元数据传递本地化标题/消息；若主要通知可能不可见，包含可见兜底通知；实际可行时写入简短成功/失败日志。
- 创建或修改计划通知后，实际可行时验证通知动作。对于可执行动作，运行一次无害短测试，或以其他方式确认动作能成功完成，再依赖计划时间。
- 将生成的通知辅助文件、元数据文件和日志文件视为该提醒的受控相邻产物。不要把 `powershell.exe`、`schtasks.exe`、shell 解释器、通知守护进程、app runtime 或共享运行时文件视为受控产物。

## 脚本与目录位置

- 创建新任务时，先查询范围内最新一条任务记录的目录并复用其父目录，然后在其中创建 `<日期>/<某一项任务>/` 子目录存放文件。不要把新任务文件放进上一条任务目录里。
- 如果没有查到任何范围内任务或可信元数据，且用户没有提供目录，不要创建提醒；必须提示用户提供一个目录后才能继续。
- 创建、查询、查看、更新、删除或审计之后，在回复末尾补充一句“目录位置：`...`”。如果没有可用目录，写“目录位置：未设置”。

## 安全规则

- 仅管理明确用于定时提醒且明确属于此命名空间或前缀的资源。
- 不要创建、更新、禁用、启用或删除无关的计划任务资源。
- 不要操作宽泛的调度器路径、全部 jobs、全部启动项、厂商更新任务、安全软件任务、浏览器更新任务或操作系统托管任务。
- 任何没有 `AI-Reminder-` 前缀或 `AI-Reminders` 命名空间的资源都视为范围外。
- 用户要求修改不明确属于此范围的任务时，说明此 skill 只管理带前缀的提醒资源。
- 除非用户明确要求系统级任务并理解权限影响，否则优先使用用户级计划任务。
- 删除、覆盖、禁用等破坏性操作前，确认精确的资源名称或 ID。

## 操作规则

通用约束（所有操作均适用）：
- 仅操作带 `AI-Reminder-` 前缀或 `AI-Reminders` 命名空间的资源。
- 创建前先检查过期提醒，存在时用表格展示并询问用户是否删除。
- 目录解析遵循"脚本与目录位置"规则，不重复判断。
- 操作后报告提醒 ID、平台资源名称、通知方式和目录位置。

创建：

- 生成带 `AI-Reminder-` 前缀的稳定 ID。
- 保存完整元数据：标题、消息、时间、循环规则、重要性、用户意图、通知 backend、平台动作、元数据路径，以及存在时的辅助文件/日志路径。
- 平台支持时，启用错过时间后的补跑行为。
- 创建后验证平台资源存在。

列出：

- 用 Markdown 表格返回结果，固定列：`序号` | `ID` | `标题` | `重要性` | `计划时间` | `循环规则` | `状态` | `下次运行` | `上次运行` | `通知方式` | `目录位置`
- 没有匹配资源时，清楚说明未找到结果。

查看：

- 用 Markdown 表格展示单个资源关键字段，补充不一致、权限限制或执行失败详情。
- 元数据与调度器资源不一致时，明确报告差异。

更新：

- 保留稳定 ID，仅修改匹配前缀的资源及其受控元数据。
- 沿用该提醒原目录；不可确定时按"脚本与目录位置"规则处理。
- 仅当原地更新不安全或平台不支持时，才重建受控资源。

删除：

- 仅删除用户指定的精确带前缀资源及其受控相邻产物（元数据、辅助脚本、日志）。
- 删除前确认每个产物明确归属于该精确提醒 ID。
- 报告已删除的调度器资源和相邻产物。

审计：

- 仅检查 `AI-Reminders` 命名空间内的孤立元数据或孤立计划任务资源。
- 仅为受控资源提供修复建议或修复操作。

## 用户沟通

使用用户的语言回复。如果无法安全访问操作系统调度器或通知系统，说明阻碍因素以及需要的权限或用户登录状态。
