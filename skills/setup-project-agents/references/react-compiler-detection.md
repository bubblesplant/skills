# React Compiler 检测

仅在可能选择“React 手动记忆化”资产时读取本文件，检测只决定该规则及入口是否新增或合并。

## 判断依据

- 按当前 React 作用范围独立检查实际编译其源码的各构建模式及必要的共享配置；非 React 范围不检测。
- 检查限于用户指定范围内的构建链及其直接引用的必要共享配置。由消费方编译的包，只核对该范围内可确认的消费方；构建链依赖范围外消费方、无法求值的动态配置等而不能确认时，停止追踪并归为“无法确认”，不扩大为全仓或外部项目审计。
- 以当前安装版本支持且实际启用的 Compiler 插件或选项为依据，例如 Babel 注册 `babel-plugin-react-compiler`、Vite 的 `react({ compiler: true })`、Next.js 的 `reactCompiler: true`；有效的配置对象形式也算启用。
- 依赖记录、React 19、ESLint/healthcheck 工具、源码指令、文档示例或生成产物不能单独证明启用；已关闭或未接入实际构建链的配置不算。
- 注解模式、`sources` 或过滤范围限制不改变“已启用”的判断。只读检查现有文件，不安装依赖、修改配置或运行完整业务构建。

## 结果与处理

| 结果 | 判断条件 | 初始化行为 |
| --- | --- | --- |
| 已启用 | 任一实际构建模式明确启用 | 不新增、不合并 `React手动记忆化.md`，也不添加对应入口。 |
| 确认未启用 | 当前范围的实际构建链完整可确认，所有实际模式均检查完毕且没有启用证据 | 同时新增或合并规则文件与对应入口。 |
| 无法确认 | 没有明确启用证据，但实际构建链、消费方或配置值无法在上述边界内确认 | 跳过当前范围的规则和入口，报告未确认项；不影响其他范围。 |

不自动删除或迁移目标项目已有规则；当前范围已启用 Compiler 时停止合入，并报告现有规则与适用条件不一致。只有用户明确要求清理时才处理已有内容。
