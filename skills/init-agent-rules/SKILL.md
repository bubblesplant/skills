# 初始化项目 AI 规则

将 `assets/` 中适用于目标项目的个人规则实际写入项目，并与已有规则合并。`assets/` 是规则与入口模板的来源；本文件只规定初始化流程，不重复规则正文。

## 处理边界

- 使用用户指定的项目或包；未指定时使用当前工作目录所属项目。不要自动扩大到外层仓库、脚手架仓库或用户主目录。
- 只修改目标范围内的 `AGENTS.md`、`.agents/rules` 及其必要链接。不要为落实规则而修改业务代码、依赖、构建配置或生成文件。
- 初始化前读取目标范围内已有的 `AGENTS.md`、`.agents/rules` 及其引用文件，并遵循仍然有效的项目约定和工具维护说明。
- 根据工作区配置、包清单、构建入口和源码职责识别单体项目、monorepo 及真实子包；不要仅凭 `apps`、`packages` 或嵌套 `package.json` 判定。
- 初始化是用户本次明确发起的一次语义合并，不把目标目录镜像成 `assets/`，也不因 `assets/` 后续变化自动回写已经初始化的项目。对本次明确指定的初始化或补齐范围，仍须将适用的个人规则基线与现有规则完整比较并合并。只有用户明确要求时才整理、移动、删除已有规则，或对已接入项目执行模板升级。

## 初始化流程

1. 确定项目根、用户指定范围，以及每个真实包的职责、框架和现有规则作用域。
2. 枚举 `assets/`，并完整读取 [规则选择清单](references/rule-selection.md)。按根项目和每个包分别选择适用的规则资产与入口资产。
3. 只有存在 React 手动记忆化候选规则时，才完整读取 [React Compiler 检测](references/react-compiler-detection.md)，并对每个 React 作用范围独立判断。非 React 范围不执行该检测。
4. 沿用目标项目已有且清晰的规则布局；缺少布局时使用选择清单中的默认位置。只为确有适用规则的范围创建入口和规则目录。
5. 按下节逐条比较并合并规则，再替换模板参数、适配真实路径和重算相对链接。路径或示例可以适配，个人规则的约束含义和强度不能被弱化。
6. 写入最终文件后检查全部入口、链接、参数、作用范围和条件规则，并审查差异，确认没有修改本次范围外的内容。

## 与已有规则合并

- 选中的资产是用户个人规则基线。不能仅因目标已有同主题约定，就跳过资产中缺失的要求或把“必须”“禁止”改成建议。
- 按作用范围、触发条件、具体要求、约束强度和例外逐条比较语义，不按标题、文件名或文字相似度判断是否重复。
- 目标条款已完整覆盖资产意图时，复用目标内容、文件位置和有效入口，不重复添加，也不为统一措辞而改写。
- 目标只覆盖部分意图时，将缺失要求合入最接近的现有规则文件；没有合适文件时才新增规则文件，并补齐对应的按需入口。
- 同主题但不冲突的项目细节与个人规则同时保留。路径、别名、命令、扩展名和示例按项目实际适配，但不得改变规则本身的义务。
- 规则应落在最窄且正确的作用范围内。保留根、包和深层局部规则的边界，不把包约定提升为全局规则，也不把全局个人规则无故缩小到单个包。
- 表面冲突先通过拆分作用范围、触发条件或明确例外化解；更具体的规则只在其明确范围内生效。
- 同一范围内确实无法兼容时，不写入两条互相矛盾的规则。用户本次已明确优先级时按其要求处理；否则暂缓该冲突条款，并在交付中并列说明资产要求、目标要求、作用范围和待决定项，不能静默忽略个人规则。
- 保留无关内容、注释、工具维护块和有效链接。`assets/` 中的删除或改名不授权删除、移动目标项目内容。

## 完成检查

- 将每项适用资产归类为“已有覆盖、已合并、已新增、条件不适用或冲突待定”，确认没有遗漏清单中的适用规则。
- 检查新增或修改的规则都能从正确作用范围的入口按需找到；本地链接及其标题片段可解析，所有模板参数已替换，入口条件与最终规则一致。
- 对每个 React 作用范围记录 Compiler 判断：已启用或无法确认时不新增手动记忆化规则及入口；确认未启用时规则与入口必须同时存在。
- 检查没有给非 React 包加入 React 规则，没有给纯 UI 包加入页面规则，也没有为无专属规则的包创建空入口。
- 审查最终差异，并确认相同输入再次执行不会重复追加表格、章节或规则副本。只运行与规则文档相关的格式和链接检查。
- 简短交付新增、合并或复用的规则位置，以及条件跳过项、未确认项和冲突；不要只给目录建议而不实际初始化。
