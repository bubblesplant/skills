# 网站复刻

使用这个 skill 时，全程用中文沟通和记录。目标不是凭视觉印象直接重写页面，而是先把原站的交互状态摸清楚，再按状态依赖逐条实现，并用截图持续对比到一致。

## 绝对流程

不要跳过阶段 2 直接写代码。即使用户一开始就要求“直接实现”，也要先完成阶段 1 和阶段 2，并在阶段 2 结束后停住，等待用户明确说出“开始写代码”。

只有当用户已经明确说“开始写代码”时，才进入阶段 3。实现完成后还不能直接结束，必须继续执行“原站 vs 复刻站”的循环对比，直到状态依赖表里的所有触发项都逐一验证一致。

## 阶段 1：侦察

1. 用 Playwright 打开原站页面，等待 `networkidle`。
2. 截取默认状态全页图，作为基准图。
3. 枚举页面内可交互元素，至少覆盖：
   - `checkbox`
   - `radio`
   - `tab`
   - `select`、combobox、menu、dropdown
   - `button`
   - 其他明显会改变页面状态的控件
4. 逐一触发控件。每次触发后截图，并记录“触发了什么 -> 页面发生了什么变化”。
5. 对可能危险或不可逆的操作先停下确认，例如支付、删除、提交真实表单、退出登录、发送消息、跳转外部站点。
6. 如果一个控件会展开新的控件或子状态，继续侦察新增状态，并记录它依赖哪个父状态。
7. 尽量让每个触发项从可复现的前置状态开始。若必须按连续流程触发，明确记录前置步骤。

每条侦察记录至少包含：

```text
编号：
模块：
元素文本/role/selector：
触发动作：
触发前状态：
触发后变化：
依赖状态：
截图：
备注：
```

## 阶段 2：分析

在侦察完成后，先输出分析结果，不写实现代码。

必须输出“状态依赖表”：

```text
模块 | 触发条件 | 依赖状态 | 变化结果
```

必须输出“模块间数据流”：

```text
A 模块的输出 -> B 模块的输入
```

分析时要归纳：

- 哪些状态是全局状态，哪些只属于局部模块。
- 哪些控件只改变样式，哪些会改变数据、列表、表单、图表、URL、弹窗或网络请求。
- 哪些模块读取同一份状态。
- 哪些交互存在顺序依赖、互斥关系、默认值或重置行为。
- 哪些状态无法安全触发，并说明原因。

阶段 2 结束时，用一句明确的话停止：

```text
侦察和状态分析已完成。等你说“开始写代码”后，我再进入实现阶段。
```

## 阶段 3：实现

只有用户明确说“开始写代码”后执行。

1. 先搭静态结构，不急着写复杂状态逻辑。
2. 复用项目已有技术栈、组件、样式系统和路由方式。
3. 按状态依赖表逐行实现交互逻辑。
4. 每实现一行，就打开复刻站触发对应状态，截图并与原站同状态截图对比。
5. 若发现不一致，立即修改该行对应实现，再截图对比，直到该状态一致后再进入下一行。

实现记录建议按这个格式维护：

```text
状态依赖表行号：
实现文件：
原站截图：
复刻站截图：
差异：
修正：
结论：
```

## 最终循环对比

当状态依赖表所有行都实现后，必须再进行完整回归：

1. 同时打开原站和复刻站。
2. 从默认状态开始截图对比。
3. 按状态依赖表顺序，逐一在两边触发同一个交互。
4. 每个状态都截图对比并记录结论。
5. 只要发现差异，就继续更改复刻站，再回到对应状态重新对比。
6. 直到默认状态和状态依赖表中的所有触发状态在两边都一致，才可以结束任务。

最终回复必须说明：

- 已覆盖的状态数量。
- 仍有差异的状态；如果没有，明确写“未发现剩余差异”。
- 无法验证的状态及原因。
- 运行过的检查、构建或测试命令。

## 截图与记录约定

优先把截图和分析产物放在项目内清晰的临时目录，例如：

```text
artifacts/website-replica/
  original/
  replica/
  comparisons/
  state-dependency-table.md
  data-flow.md
```

如果项目不适合写入这些目录，就使用当前任务允许的临时目录，并在回复里说明位置。

截图命名要能看出顺序和状态，例如：

```text
00-original-default.png
01-original-filter-open.png
01-replica-filter-open.png
01-comparison-filter-open.png
```

## 质量标准

- 不凭记忆补交互，必须从侦察记录或用户确认中来。
- 不因为视觉大体相似就跳过状态验证。
- 不只验证默认页，必须覆盖状态依赖表中的每一行。
- 保持用户循环清晰：阶段 2 停止等确认；阶段 3 每批实现后给出截图对比结论。
